### Formalizations in the Rocq proof assistant

This subdirectory contains some attempts at formalizing some definitions and proofs in the Rocq proof assistant. This turned out to be very useful, as we realized some of our initial approaches weren't as promising as they had seemed.

The main "successful" formalization is in [`typed_pattern_matching.v`](typed_pattern_matching.v), which defined pattern matching in conjunction with typing. We were able to prove that typed pattern-matching exhibits properties similar to those of classical logic, namely the law of the excluded middle (either a value `v` matches `p` with type `t`, or it does not), and double negation (`v` matches `p` iff `v` matches `not not p`). We then formalized how typed patterns can be seen as sets of values, and proved how operations between patterns naturally translate to operations between sets. For instance, the set `[| p1 or p2 |]` is equal to `[| p1 |] u [| p2 |]`, and so on. Not quite a morphism a priori (we would perhaps need to quotient patterns by some equivalence relation). The rest of the file properly defined matrix specialization (using the Rocq `Equations` module to satisfy termination), and there are some elements of proof for its specification, though some parts were were abandoned on `admit`. The relevant notes are in [`../docs/typing.typ`](../docs/typing.typ).

The two other files, `untyped_pattern_inclusion1.v` and `untyped_pattern_inclusion2.v` were different attempts at studying pattern negation and pattern-matching exhaustivity. Our initial idea was to extend pattern-matching as a relation not just between values and patterns, but between patterns in general. Judgments would have then looked like `p <= q`, which can be read "`p` is included in `q`", or maybe "`q` is more general than `p`". However we found it very difficult to describe this relation by induction, as we realized we were essentially trying to define inclusion with inference rules. With this definition, we would then have been able to define pattern-matching exhaustivity as `omega <= p`, i.e. "`p` matches everything". Unfortunately, the main difficutly came from trying to define `p <= q1 or q2`, which is not so easy to reason about when the set `p` overlaps with both sets `q1` and `q2`. This approach was essentially abandoned. A more readable version of the inference rules are found in [`../docs/inclusion.typ`](../docs/inclusion.typ).
